# Database restore drill — 2026-11-24

## Result

Passed for the application-owned `public` schema and data, with no paid cloud
resources created.

- Downloaded the encrypted artifact from the completed production backup run.
- Decrypted it only in a temporary local directory and verified every embedded
  SHA-256 checksum before restoring.
- Restored the roles, application schema, and all `public` table data into a
  temporary PostgreSQL 17 instance.
- Confirmed exact matches for all 13 public table row counts, table ownership,
  RLS state, policy definitions, table grants, and default privileges.
- Confirmed the restored snapshot included 12 trades and 472 wallet events.
- Stopped the temporary database and deleted the plaintext dump, identity copy,
  logs, and database files after verification.

## Scope and limitation

This was a no-cost local application-data restore drill. Supabase-managed Auth,
Storage, Vault, and platform bootstrap objects were not recreated locally. A
full hosted Supabase disaster-recovery drill still requires an empty isolated
Supabase project or branch. No branch or project was created during this drill,
so it created no recurring charge.
